Supabase 配置指南

三店联动红包系统 v4.0 · 从 Render 临时存储迁移到 Supabase 持久化数据库
预计耗时：10-15 分钟 · 全程免费

为什么要做这一步？ Render 免费版使用临时文件系统，服务休眠唤醒或重新部署后，所有运行时写入的文件（红包领取记录、统计、日志、上传图片）都会丢失。 Supabase 提供免费的 PostgreSQL 数据库 + 对象存储，数据持久保存，永不上限丢失。
1 注册 Supabase 账号
  1. 打开 https://supabase.com
  2. 点击右上角 Start your project
  3. 用 GitHub 账号登录（推荐，省去注册步骤）
  4. 授权 Supabase 访问你的 GitHub
已经有 Supabase 账号？直接登录跳到第 2 步。
2 创建新项目
  1. 登录后点击 New Project
  2. 填写项目信息：
    • Name：填 redpacket-system（随意取）
    • Database Password：设置一个强密码，记下来
    • Region：选 Singapore (Southeast Asia)（离中国最近）
    • Plan：选 Free（免费版）
  3. 点击 Create new project
  4. 等待 1-2 分钟，项目创建完成
注意：数据库密码这次用不到（我们用 API Key 访问），但建议记下来以防万一。
3 执行建表 SQL
  1. 在左侧菜单点击 🧭 SQL Editor
  2. 点击 + New query
  3. 将下面的 SQL 全部粘贴进去
  4. 点击 Run（或按 Ctrl+Enter）
-- 建表脚本（直接复制粘贴执行） -- 1. 统计数据表 CREATE TABLE IF NOT EXISTS stats ( id INTEGER PRIMARY KEY DEFAULT 1, scan_count INTEGER DEFAULT 0, redpacket_claimed INTEGER DEFAULT 0, redpacket_used INTEGER DEFAULT 0 ); INSERT INTO stats (id, scan_count, redpacket_claimed, redpacket_used) VALUES (1, 0, 0, 0) ON CONFLICT (id) DO NOTHING; -- 2. 红包领取记录表 CREATE TABLE IF NOT EXISTS redpackets ( id TEXT PRIMARY KEY, pin TEXT NOT NULL, phone TEXT NOT NULL, phone_masked TEXT, restaurant_id INTEGER NOT NULL, restaurant_name TEXT, restaurant_color TEXT, amount INTEGER, min_spend INTEGER, claimed_at TIMESTAMPTZ, expire_at TIMESTAMPTZ, used BOOLEAN DEFAULT FALSE, used_at TIMESTAMPTZ ); CREATE INDEX IF NOT EXISTS idx_redpackets_phone_restaurant ON redpackets(phone, restaurant_id); CREATE INDEX IF NOT EXISTS idx_redpackets_claimed_at ON redpackets(claimed_at DESC); -- 3. 餐厅数据表 CREATE TABLE IF NOT EXISTS restaurants ( id INTEGER PRIMARY KEY, data JSONB ); -- 4. 操作日志表 CREATE TABLE IF NOT EXISTS logs ( id TEXT PRIMARY KEY, created_at TIMESTAMPTZ DEFAULT NOW(), action TEXT, details TEXT, admin TEXT ); CREATE INDEX IF NOT EXISTS idx_logs_created_at ON logs(created_at DESC); -- 启用行级安全（只允许 service_role 访问） ALTER TABLE stats ENABLE ROW LEVEL SECURITY; ALTER TABLE redpackets ENABLE ROW LEVEL SECURITY; ALTER TABLE restaurants ENABLE ROW LEVEL SECURITY; ALTER TABLE logs ENABLE ROW LEVEL SECURITY;
执行成功后会显示 Success. No rows returned.
4 创建图片存储桶 (Storage Bucket)
  1. 在左侧菜单点击 📦 Storage
  2. 点击 + New bucket
  3. 填写：
    • Name：uploads（必须叫这个名字）
    • Public bucket：✅ 勾选（允许公开读取图片）
  4. 点击 Create bucket
必须勾选 Public bucket，否则上传的图片在用户端无法显示。
5 获取 API 密钥
  1. 在左侧菜单点击 ⚙️ Project Settings（最底部齿轮图标）
  2. 点击 API
  3. 找到以下两个值，复制保存好：
    • Project URL：https://xxxxx.supabase.co
    • service_role secret：点 Reveal 后显示一长串 eyJ...
⚠️ 安全警告
service_role 密钥拥有数据库完全控制权限，绝对不要放入前端代码或公开仓库。 它只配置在 Render 的环境变量中，不会出现在代码里。
不要用 anon key，要用 service_role key。 区别：anon key 受 RLS 策略限制（我们禁用了所有公开访问），service_role key 可绕过 RLS 完全控制数据库。
6 在 Render 配置环境变量
  1. 打开 Render Dashboard
  2. 点击你的 Web Service（yi-pu-xi-gong-hong-bao-xi-tong）
  3. 左侧菜单点击 ⚙️ Environment
  4. 添加两个环境变量：
Key: SUPABASE_URL Value: https://xxxxx.supabase.co Key: SUPABASE_SERVICE_KEY Value: eyJhbGciOiJIUzI1NiIsInR5...(你的 service_role 密钥)
  1. 点击 Save Changes
  2. Render 会自动重新部署（约 1-2 分钟）
Value 不要加引号，直接粘贴 URL 和密钥原文即可。
7 验证部署
  1. 等待 Render 部署完成后，访问：
    https://yi-pu-xi-gong-hong-bao-xi-tong.onrender.com/api/health
  2. 如果返回类似以下内容，说明 Supabase 已生效：
    { "success": true, "version": "4.0", "storage": "supabase" }
  3. 如果 storage 显示 json-file，说明环境变量没配对，检查第 6 步。
